"复述"沿用外部汇总的口径：回答去首尾空白后与题目相同为完全复述；去空白后 SequenceMatcher 相似度 ≥0.90 为近似复述。

## 1. 结论

1. 复述只出现在"LoRA + 非空 System + 非思考模式"的组合下。原版模型、思考模式、不传 System、空 System 四组各只改变一个条件，复述都是 0/50。
2. 训练数据核查排除了三种解释：训练数据教会了抄题、测试题泄漏、聊天模板不一致。
3. 判断：训练与推理的输入格式不一致，且非思考模式下的业务任务没有训练覆盖。训练样本全部不带 System；非思考样本几乎都是身份类短问答。为什么空 System 不触发、"你是助手"会触发，具体机制仍未解释。
4. v0.1.14 的配方几乎原样照搬了 ms-swift 官方的 Qwen3 自我认知示例。该示例只演示怎样改身份，不覆盖"带 System + 非思考 + 业务长任务"这种部署方式。
5. 需要服务方决定：被测和上线用原版还是 LoRA（第 6 节）。

## 4. 0.70–0.90 相似度区间

- 这个区间的短回答只出现在"LoRA + 非空 System + 非思考"条件下；原版、思考模式、不传或空 System 各组的最高相似度只有 0.56。
- 如果按回答不超过 100 token 计数：LoRA 完整System 19/50（外部汇总记 11），P1 17/20，P2 9/20，P3 18/20。
- 读原文后发现这个区间是混合的，不能直接都算作复述：
  - 合格的精简改写：防火题 LoRA 第 12、43 次，P2-08，P3-02；
  - 照抄题目再加一句判断：第 36、50 次，P3-05、P3-10、P3-16；
  - 失败：P3-07 照抄且没有纠正；P1-16 改错了事实。
  - 全量数据里抽看 4 条 R3300：G0922#1、G1047#2、G1165#1 是失败，G1004#2 是勉强合格的最小改动。
- 正确答案本来就要重述题中事实，所以相似度只能筛出"确定是复述"的回答。比较 P0–P3 孰优孰劣，需要对这个区间做人工标注。
- P1、P2、P3 都加了"修订任务输出修订后的正文"这类规则，而 P1 复述最多。题目没有把待改原文和指令分开，这类规则可能促使模型把整道题当作正文返回。几处是同时改的，不能据此定因；但说明不宜靠改 System 措辞来治复述。

## 7. 建议

1. **先定模型（服务方）**：
   - SFT 项目自己的选型报告建议默认用原版的非思考模式；v0.1.14 的报告结论是"不足以建议替换原版"。
   - 原版用同一份 System 时复述为 0/50。
   - 这个 LoRA 只做了身份和通用指令微调，主要好处是不带 System 也能答对身份，而线上本来就带 System。
   - 若改用原版，要先确认带 System 时身份题能达标；换模型需要全量重测，调用量需另行授权。
2. **如果保留 LoRA，下一轮训练**：见 `tested_model/sft_system_prompt.md`。要点是：
   - 训练样本带部署用的 System；
   - 非思考数据覆盖业务长任务，尤其是"给定事实 + 错误说法 + 要求纠正 + 限制条件"结构和 B6 式短题；
   - 非思考样本以"不带 `/no_think`、保留空思考块"为主；
   - 继续混入带思考过程的数据。
3. **过渡措施**：服务端在回答与问题相似度 ≥0.9 时重新生成一次。这必须是真实服务的一部分，不能只在测评时打开。
4. **评审口径**：复述应判为失败；R3300 类题目的复述等于重复了错误说法。应拒答题的复述目前记为 PENDING，见 `TODO.md`。
