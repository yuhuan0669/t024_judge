# 微调（SFT）与系统提示词

2026-10-28 整理，供被测模型下一轮微调参考。

## 现状

- `octa-carbon-sft-v0114` 微调时**没有带系统提示词**，推理时却带着约 640 token 的 `system_prompt.txt`，训练和推理不一致。
- 服务上下文窗口为 8192 token，系统提示词每次都占用上下文。
- 系统提示词 A/B 对比（`results/ab_system_prompt_20261028.md`，290 题 × 3 组）：
  - 带提示词明显优于不带：应拒答题未拒答 27→14（p=0.002）；
  - 精简新稿与现行版总体相当，R30 安全相关严重错误 17→9（p=0.021），回答更短；
  - R07（编造）和 R31（帮不上忙）三组基本不变，**提示词解决不了，需要通过训练数据改进**。

## 基本原则

训练时的输入格式要和推理时完全一致：推理用什么系统提示词，训练样本就带同一份，位置相同，对话模板相同。否则模型部署时看到的提示词和训练时学的对不上，表现不可预测。

## 三种做法

| 做法 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| 1. 每条样本带完整部署提示词 | 训练与推理用同一份长提示词 | 最一致、最稳妥 | 行为绑定提示词措辞，改提示词要重训或至少 A/B；推理时仍占几百 token |
| **2. 短提示词 + 规则写进训练数据（推荐）** | 训练和推理都只用约 100–150 token 的固定短提示词（身份、服务范围、最核心的边界），其余行为规则通过示范回答教会模型（上下文蒸馏） | 省上下文；小模型照示范学比按条文执行可靠 | 改规则需重训；训练数据必须覆盖每条规则 |
| 3. 混合 | 以带部署提示词为主，10%–30% 样本不带或用措辞略有不同的版本 | 对提示词的细微变化更稳健 | 需要额外准备变体 |

推荐做法 2，并可叠加做法 3 的少量变体。

## 训练数据需要覆盖的规则

以下行为在试跑和 A/B 中暴露问题较多，或属于 R31 最低帮助清单，需要有足够的示范样本：

1. 审校、改写他人文本时，核对事实、计算和安全说法，发现错误必须指出并改正，不照抄、不背书（R3300 类题目，R30 主要来源）。
2. 请求含违法、歧视、侵权或危害安全的要求时，一句话说明不执行该部分，完成其余合法部分；不追问实施细节；遵守题目给出的安全、隐私和授权限制。
3. 报告、台账、方案中用户未提供的数值用【待补充】占位，不编造数值、认证或检测结果（R07、R31）。
4. 引用标准或法规只写能确认的名称；不确定编号或条号时只写内容，并提示以现行原文为准（R07）。
5. 排查故障给出可执行步骤，不只建议联系专业人员；涉及电气、高温高压、有限空间等作业时提示关键安全措施，须持证的作业注明由持证人员进行（R31 清单第 2、3 条）。
6. 超出能力的请求（如远程控制设备）说明不能执行，并提供替代帮助；不声称已执行操作或已调取实时数据。
7. 不复述问题、不以自我介绍代替回答。
8. 计算后自查单位、守恒和题设限值；比较类问题核对口径和分母（沿用现行提示词的比较规则）。

## 实施注意事项

- **对话模板一致**：推理设置了 `enable_thinking: false`，Qwen3 模板此时会插入空的思考标签；训练数据必须用同一模板、同样设置生成。
- **只对回答计算损失**：系统提示词和用户输入屏蔽，不参与损失计算。
- **多轮对话**：线上有多轮对话的，训练数据要包含带系统提示词的多轮样本。
- **测试题不进训练集**：不得使用 T021/T024 测试题库中的题目或其改写，训练样本另行编写，否则评测结果失真。
- **提示词纳入版本管理**：训练所用的短提示词与部署版本一一对应，放在 `tested_model/system_prompt.txt` 并记录在 `tested_model/README.md`。

## 验证

重训后，用同一批试跑题按 `gen_answers.py` + `judge.py` 做 A/B（新模型 + 新短提示词，对比现行模型 + 现行或新稿提示词），比较各题库指标和 R07、R30、R31 的出现次数。调用量需事先说明并获得授权。
